# 盘中实盘选股与实时补 K 线设计方案(详细版)

> 状态:**已实施(2026-09-15,M1+M2)**。盘中补K三层判定、快照合成K(含adj复权换算)已落地并挂载实盘选股路径。M3 双口径对照验证与 M4 回测增强未实施。
>
> 范围:仅覆盖**当日实盘选股**路径。回测选股路径不涉及实时行情,不在本文档范围内(见 0.3)。

## 0. 背景速览

### 0.1 需求动因

用户希望在**尾盘(如 14:45)执行策略选股,选出股票当日买入**,从而比"信号次日开盘买入"**提前一天解锁卖出权**。

A 股 T+1 制度下,两种方案的时间轴对比:

```
现状方案(信号 T 日收盘 → T+1 开盘买入):
  T 日 15:00  ──信号生成──>  T+1 日 09:30 ──买入──>  T+1 全天(不可卖) + 隔夜  ──>  T+2 日 09:30 起可卖

目标方案(14:45 选股 → T 日尾盘买入):
  T 日 14:45  ──选股+买入──>  T 日尾盘 15 分钟 + 隔夜  ──>  T+1 日 09:30 起可卖(全天有操作权)
```

| 对比维度 | 现状(次日开盘买入) | 目标方案(尾盘买入) |
|---|---|---|
| 信号 → 买入间隔 | 隔夜 | 15 分钟内 |
| 成交价与信号价 | 可能高开,滑点大 | ≈收盘价,滑点小 |
| 买入 → 可卖(T+1 制度) | **1 个完整交易日 + 隔夜** | **尾盘 15 分钟 + 隔夜** |
| 买入当天破位 | 无操作权,只能看着 | 已收盘,风险仅为隔夜跳空 |
| 次日(T+1) | 持仓中但**无操作权** | **全天有操作权**:低开可止损、冲高可止盈 |

核心差异:同样做隔日超短,目标方案少扛一个完整的"不可操作交易日"。对止损纪律是实质性改善,不是小优化。

### 0.2 核心方案一句话

盘中执行选股时,数据库里没有今日 K 线(日 K 收盘后才落库),因此通过**实时行情接口拉快照 → 合成今日"未收盘日 K" → 与历史 K 在内存中拼接 → 喂给策略引擎**,合成 K **不落库**(收盘后正式 K 线会入库,不可污染数据库)。

### 0.3 目标与边界

- **目标**:盘中任意交易日时刻(重点是 14:45 尾盘窗口)可触发策略选股,信号口径尽可能接近收盘口径
- **边界**:
  - 仅实盘选股路径补 K;**回测路径纯读库,不查实时行情,不引入任何实时依赖**(回测遍历的历史日期,当时 K 线早已收盘落库)
  - 两条路径共用**同一个策略引擎**:策略代码保持"输入完整 K 线序列 → 输出信号"的纯函数形态,不感知数据来源。唯一变量是"最后一根 K 是合成还是正式"
  - 不做盘中定时自动下单;选股结果仍走现有信号展示/落库链路,买入由人工执行

### 0.4 决策记录(讨论中否决的备选)

| 备选方案 | 结论 | 原因 |
|---|---|---|
| T+1 开盘买入 + 盘中实时止损 | ❌ 否决 | **T+1 制度硬伤**:当日买入当日不能卖,"盘中实时止损"不成立;买入后必须扛满 1 个交易日 + 隔夜才有操作权 |
| 补 K 判定只用"最后一根 K 日期 == 今天" | ❌ 否决 | 过于粗暴:周末/节假日会误判需要补 K;停牌股、落库延迟场景处理不了 |
| 以快照接口为唯一真相源(每次选股都调快照,不做日期比较) | ❌ 否决 | 非交易日白白调接口;收盘后已落库时仍是冗余调用;增加外部依赖与延迟 |
| 三层判定(交易日 → 日期比对 → 快照兜底) | ✅ 采纳 | 见第 1 章 |

## 1. 补 K 判定逻辑(三层)

在**实盘选股路径拉完 K 线之后、喂给策略引擎之前**,做一次统一补 K。

### 1.1 判定流程

```
1. 今天是不是交易日?(查 workday.db / 接口)
   ├─ 不是(周末/节假日)→ 不补 K,直接用库里的 K 跑
   └─ 是 → 进入第 2 步
2. 最后一根 K 的日期 == 今天?
   ├─ 是 → 今日 K 已落库(收盘后),直接用
   └─ 否 → 进入第 3 步
3. 拉实时快照,合成今日 K 补上
   ├─ 快照拉到 → 合成 K 日期用「快照返回的行情日期」
   └─ 快照拉不到(停牌/接口失败) → 跳过该股,不静默用旧数据
```

Go 风格伪代码:

```go
// patchIntradayKline 在实盘选股路径拉完 K 线后调用。
// 返回值:补 K 后的完整序列、是否发生了补 K。
func patchIntradayKline(today int, isWorkday bool, rows []FormulaKline, quote *protocol.Quote) ([]FormulaKline, bool) {
    if !isWorkday {
        return rows, false // 第 1 步:非交易日直接用库里的 K
    }
    if len(rows) > 0 && rows[len(rows)-1].Date == today {
        return rows, false // 第 2 步:今日 K 已落库
    }
    // 第 3 步:合成 K(quote 为 nil 说明快照拉不到 → 调用方跳过该股)
    synth, ok := buildSyntheticKline(rows, quote)
    if !ok {
        return rows, false
    }
    return append(rows, synth), true
}
```

### 1.2 三种执行时机覆盖

| 执行时机 | 第 1 步 | 第 2 步 | 结果 |
|---|---|---|---|
| 周末/节假日复盘 | 非交易日 | 不查 | 用库里 K 跑 → **收盘口径信号**(与回测完全一致) |
| 交易日盘中(14:45) | 交易日 | ≠ 今天 | 补 K → **盘中口径信号**(目标能力) |
| 交易日收盘后、K 未落库 | 交易日 | ≠ 今天 | 补 K,但快照价=收盘价 → **合成 K 等价正式 K**,信号一致 |

第三行值得注意:收盘后 15:00~落库前这段窗口,即使触发补 K,拉到的快照就是收盘快照,拼出来的 K 与正式 K 一致,不引入口径偏差。

### 1.3 实现细节

- **顺序有讲究**:交易日判断(查库,毫秒级)在前,日期比对(内存比较,免费)在中,补 K(调行情接口,最贵)在最后。大多数情况(非交易日、已落库)根本不会调行情接口
- **日期用 `!=` 不用 `<`**:最后一根 K 日期理论上不可能大于今天(未来数据);用 `!=` 更简单,万一数据异常还能被快照兜底纠正
- **补 K 失败兜底**:宁可少选,不选错。查不到快照就跳过该股,不要拿昨天的 K 硬算——那样今日的均线、量能因子全部滞后一天,选出来的信号是假的
- **幂等**:盘中多次触发选股,每次"快照 + 重建合成 K",内存中覆盖,不落库,结果一致

## 2. 合成 K 线构造

### 2.1 字段映射(tdx 快照 → FormulaKline)

实时快照来源:`GET /api/quote` → tdx `GetQuote` → `Quote.Kline`(tdx 协议中行情快照自带一根当日 K 线)。

tdx `protocol.Kline` 字段(`packages/tdx-core/protocol/model_kline.go`):

| tdx 字段 | 类型 | 含义 |
|---|---|---|
| `Last` | Price | 昨日收盘价(真实价,不复权) |
| `Open` | Price | 今日开盘价 |
| `High` | Price | 今日最高价 |
| `Low` | Price | 今日最低价 |
| `Close` | Price | 收盘价;**当天=最新价/实时价** |
| `Volume` | int64 | 成交量,**单位:手** |
| `Amount` | Price | 成交额 |
| `Time` | time.Time | 行情时间 |

合成 `FormulaKline`(`services/selection-worker/formula_worker.go` 46 行)的映射:

| FormulaKline 字段 | 来源 | 说明 |
|---|---|---|
| `Date` | 快照 `Kline.Time` 的日期部分 | **用行情日期,不用本地日历"今天"**(防长假/周末误标) |
| `Time` | 快照时间 | 可选 |
| `YClose` | 快照 `Last` × adj | adj 为复权换算因子,见 2.2 |
| `Open` | 快照 `Open` × adj | 同上 |
| `High` | 快照 `High` × adj | 同上 |
| `Low` | 快照 `Low` × adj | 同上 |
| `Close` | 快照 `Close`(现价)× adj | 同上 |
| `Vol` | 快照 `Volume` 直接透传 | **单位一致(手),无需转换**——现有转换层 `protocolKlinesToFormulaRows`(`server_automation.go` 1194 行)也是直接透传 `float64(item.Volume)` |
| `Amount` | 快照 `Amount` | 元 |

**涨跌幅不用合成 K 计算**:直接用 tdx `Kline.RiseRate()`(协议自带方法,基于真实价计算),避免复权换算引入误差。

### 2.2 复权换算(最高优先级,易静默失真)

**问题**:库内历史日 K 为**前复权价**,实时快照为**真实成交价(不复权)**。两者不能直接拼接——除权股会在最新一天出现假暴涨/暴跌,均线、量比、突破判断全部错乱。

**数据源事实**(查证于 2026-09-15):

- 选股读 K 线入口 `loadFormulaKline`(`formula_worker.go` 186 行):优先走 market-service `/api/kline-history`(hikyuu 优先,回退 tdx),回退路径直连同花顺前复权 `getQfqKlineDay`(`market_helpers.go` 12 行,`THS_QFQ`)。两条路径日 K 均为前复权
- 项目**没有本地自建的复权因子计算**,前复权价格直接来自数据源

**换算方案(比值法)**:

```
adj = 历史 K 最后一根的 Close(前复权) / 快照 Last(真实昨收)
合成 K 的 O/H/L/C = 快照价格 × adj
```

**原理**:非除权日两源价格基本一致,adj ≈ 1,合成 K ≈ 真实价;除权除息日,前复权昨收与真实昨收的比值恰好等于除权调整比例,用它缩放今日真实价即可归入前复权口径。

**实例演算(10 送 10 除权日)**:

```
真实行情:昨收 50 元,今日开 25 元,现价 26 元,最高 26.5,最低 24.8
历史 K(前复权)最后一根:Close = 25 元(除权前 50 元 ÷ 2)
adj = 25 / 50 = 0.5
合成 K:
  YClose = 50 × 0.5 = 25.0   ← 与前一根 K 的 Close 无缝衔接,无假缺口 ✓
  Open   = 25 × 0.5 = 12.5
  High   = 26.5 × 0.5 = 13.25
  Low    = 24.8 × 0.5 = 12.4
  Close  = 26 × 0.5 = 13.0
拼接序列:…, 25.0, (12.5/13.25/12.4/13.0)  ✓ 前复权语义正确
涨跌幅:用 RiseRate() = (26-25)/25 = +4%(不复权原值)✓
```

**兜底与噪声**:

- `Last` 或历史最后 Close 为 0 时,adj 视为 1(裸拼,宁可有口径瑕疵也不崩)
- 两源价格在非除权日可能差几分钱(源差异/四舍五入),adj 会略偏离 1;对 14:45 信号影响量级极小(远小于 1%),**实施后可记录 adj 序列观察**(列入开放问题 5.1)
- 实施前需确认:同花顺前复权口径与 tdx 真实价的日常一致性(用最近 N 个交易日的 `qfqClose / rawClose` 序列验证)

### 2.3 其他细节

| 点 | 处理方式 |
|---|---|
| 停牌股 | 快照里无今日行情(`Quote` 为空或 `Kline.Time` 非今日)→ 跳过该股(与回测"停牌跳过"口径一致) |
| 新股/次新(K 线不足) | 历史 K 为空时无法算 adj → adj=1 裸拼;策略侧本身有最小 K 线数要求(calcCount),信号生成会自然跳过,补 K 层不必特判 |
| 集合竞价阶段(9:15-9:25) | tdx 快照可用但价格未定型、Open 波动大;本方案目标窗口是 14:45,竞价阶段行为不做承诺 |
| 14:57 后 | 尾盘集合竞价价格锁定,最后 3 分钟信号基本等于收盘信号 |
| 北交所/ST | 合成 K 只负责价格字段,限幅等交易规则由撮合引擎/信号层处理,与本方案无关 |

### 3.4 K 线结构

`FormulaKline`(`formula_worker.go` 46 行):`Date(int, YYYYMMDD) / Time / YClose / Open / High / Low / Close / Vol / Amount`。`Vol` 单位与 tdx `Volume` 一致(**手**),转换层直接透传不换算。

## 4. 边界场景与兜底

| 场景 | 行为 | 依据 |
|---|---|---|
| 非交易日(周末/节假日) | 不补 K,直接用库里的 K | 第 1 步交易日判断 |
| 交易日,今日 K 已落库 | 不补 K,直接用 | 第 2 步日期比对 |
| 交易日盘中(目标场景) | 拉快照合成 K | 第 3 步 |
| 交易日收盘后、落库前 | 补 K,但快照=收盘快照,合成 K 等价正式 K | 1.2 第三行 |
| 停牌股 | 快照无今日行情 → 跳过该股 | 与回测"停牌跳过"口径一致 |
| 快照接口异常/超时 | 跳过该股,不静默用旧数据 | 宁可少选,不选错 |
| 除权除息日 | adj 比值法自动归入口径,无假缺口 | 2.2 |
| 新股/次新(历史 K 不足) | adj=1 裸拼;策略侧按 calcCount 自然跳过 | 2.3 |
| 盘中多次触发 | 重建合成 K,内存覆盖,幂等,不落库 | 1.3 |

## 5. 信号口径与验证计划

### 5.1 开放问题(核心未知数)

1. **14:45 口径 vs 收盘口径的信号偏差**:盘中合成 K 的 Close 是 14:45 现价而非收盘价,信号可能"收盘后消失"或"收盘后才出现"。偏差有多大,需要数据回答
2. **adj 比值噪声**:同花顺前复权与 tdx 真实价的日常一致性(应≈1 但非严格等于),实施后记录 adj 序列观察
3. **快照接口选型**:`GET /api/quote` vs `POST /api/quote/standard`(字段完整性、批量能力、延迟、停牌行为)

### 5.2 验证方案(人工先行,不依赖代码)

在补 K 代码落地前,先用**人工双清单对照**验证信号口径偏差:

- 每个交易日 14:45 手动跑一次选股(用系统现有能力近似),记录信号清单 A
- 收盘后(或晚上)再跑一次,记录信号清单 B
- 连续 2~3 周,统计:A/B 重合率、只出现在 A 的票的次日表现(假信号代价)、只出现在 B 的票的次日表现(漏信号代价)
- 结论标准:重合率 > 85% 且差异票无系统性劣势 → 尾盘口径可信,推进 M2;否则先解决信号敏感性问题(如调整因子在盘中价的稳定性)

### 5.3 回测增强(可选,远期)

若需回测验证"14:45 口径"的历史成功率,需在回测引擎加"盘中快照口径"模式(每个模拟日用当日 14:45 快照 K 代替收盘 K 再跑选股)。**依赖历史盘中快照数据,当前没有,不做**。
